# 「夜泉琉璃」界面实现说明

## 目标

本版以深色概念图为视觉基准，把原有 Demo 式控件收束成一套适合竖屏小游戏的「夜泉琉璃」界面：画板与四色颜料是第一视觉层，章节背景负责交代故事地点，操作按钮退到不抢画面的次要层级。

这是一套对概念图的结构、气质和视觉层级还原，并非逐像素复刻。运行时仍须兼顾 6×6、8×8、10×10 棋盘、不同手机安全区、文字可读性和 Canvas 2D 性能。

## 美术资源与代码绘制边界

生成的位图资源负责提供不规则、难以由几何图形自然模拟的绘画质感：

- `assets/art/night-spring.jpg`：泉醒章，近景泉眼与叶影。
- `assets/art/night-creek.jpg`：涧行章，幽暗溪涧。
- `assets/art/night-river.jpg`：河声章，逐渐开阔的河面。
- `assets/art/night-coast.jpg`：潮生章，海岸与潮光。
- `assets/art/night-sea.jpg`：入海章，远海夜色。
- `assets/art/pigments.jpg`：四色矿物颜料的颗粒、晕染和高光纹理。

Canvas 代码负责所有需要随关卡、分辨率或交互状态变化的部分：

- 标题、章名、剩余步数与目标色。
- 细金边棋盘、内外框、暗色承托面和棋盘阴影。
- 圆形颜料盘、选中色环和颜色名称。
- 撤销、重开、音效、观看提示与关卡册控件。
- 横向关卡导航、当前关高亮和二十关目录。
- 安全区、短屏和窄屏自适应布局。

位图加载失败或平台没有图片创建接口时，游戏仍以纯色回退方案保持可玩，不因装饰资源阻断玩法。

## 二十关背景映射

二十关按每四关一章推进，背景只承担故事氛围，不覆盖或干扰棋盘内容：

| 关卡 | 章节 | 背景 |
| --- | --- | --- |
| 0—3 | 泉醒 | `night-spring.jpg` |
| 4—7 | 涧行 | `night-creek.jpg` |
| 8—11 | 河声 | `night-river.jpg` |
| 12—15 | 潮生 | `night-coast.jpg` |
| 16—19 | 入海 | `night-sea.jpg` |

同一章节中的四关会使用轻微不同的取景缩放，形成画卷继续前进的感觉，但不再加入抢夺注意力的复杂镜头动画。

## 五种染色动效映射

五种动效全部保留，以关卡编号每五关自动换一种，25 关后循环：

| 关卡 | 动效 |
| --- | --- |
| 0—4 | 墨滴涌色 |
| 5—9 | 柔纸起伏 |
| 10—14 | 水面涟漪 |
| 15—19 | 湿笔扫染 |
| 20—24 | 色露绽放 |

当前二十关会实际覆盖前四种；第五种已保留在运行时代码中，并为后续第 20—24 关预留。浏览器故事预览页右上角的折叠面板是 development-only 的动效对比入口，可临时覆盖自动规则；选择「每5关换」即可恢复正式映射。

所有动效都沿用同一套四向递归传播层：同一层同时染色并播放同一音阶，下一传播层再升阶，避免多个方向同时扩散时音高突跳。

## 已完成验证

- 自动测试覆盖全部 20 关在 390×844、390×844（顶部 44 / 底部 34 安全区）、375×667、320×568 下的布局和输入模拟。
- 检查了棋盘、颜料盘、底部工具栏和安全区之间无几何重叠。
- 检查了六张位图资源加载、缓存及失败回退。
- 检查了 20 关关卡册、五关一组的动效映射、24 级分层音效、通关流程与微信/抖音构建产物。
- 浏览器中完成过实际选关、染色、通关弹框和窄屏预览，控制台未发现错误。

## 尚需真机与主观验收

- 微信小游戏与抖音小游戏真机上的字体回退、刘海/圆角安全区和帧率尚未验证。
- 不同设备的图片解码、显存占用与首次加载速度尚未做性能采样。
- 概念图与实现的主观接近程度、背景是否足够克制，仍以用户在目标手机上的观感为准。
